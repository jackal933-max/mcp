⏺ MCP 生活比喻：把它想成一間餐廳

  Host、Client、Server 的關係

  MCP 角色: Host
  餐廳比喻: 餐廳本身。廚房裡有主廚，也就是 AI
  模型。餐廳決定要跟哪些供應商合作，也管進出規則。
  實際例子: Claude Desktop、Claude Code、VS Code 這類 AI 應用程式
  ────────────────────────────────────────
  MCP 角色: Client
  餐廳比喻: 餐廳派去對接供應商的聯絡員。一個聯絡員只負責一家供應商，負責傳話和遵
  守雙方約定的格式。
  實際例子: Host 內部的連線元件，每個 Server 各配一個 Client
  ────────────────────────────────────────
  MCP 角色: Server
  餐廳比喻: 外部供應商，例如菜市場、肉舖、酒商。各家專門提供某種東西。
  實際例子: GitHub MCP Server、檔案系統 MCP Server、資料庫 MCP Server

  運作流程：主廚（AI）需要東西，就交代聯絡員（Client）去問對應的供應商（Server）
  ，聯絡員再把結果帶回廚房。

  重點：
  - 一個 Host 可以有很多個 Client。
  - Client 和 Server 是一對一，不會一個聯絡員同時跑好幾家。
  - MCP 本身就是聯絡員和供應商之間的「標準訂貨單格式」。只要大家都用這個格式，任
    何餐廳都能跟任何供應商合作，不用每家各寫一套對接方式。

  Tools、Resources、Prompts 的差別

  這三樣都是供應商（Server）能提供的東西，差別在於「做什麼」以及「誰決定要用」：

  ┌──────┬───────────────────────────────┬──────────────────────┬───────────┐
  │ 類型 │           餐廳比喻            │         本質         │ 誰決定用  │
  ├──────┼───────────────────────────────┼──────────────────────┼───────────┤
  │      │ 請供應商代為動手做事，例如「  │ 執行動作，可能改變外 │ AI 模型自 │
  │ Tool │ 幫我把魚切片」、「幫我送 10   │ 部狀態，例如發       │ 己判斷何  │
  │ s    │ 箱貨過來」                    │ email、建立檔案、查  │ 時呼叫    │
  │      │                               │ API                  │           │
  ├──────┼───────────────────────────────┼──────────────────────┼───────────┤
  │ Reso │                               │ 唯讀資料，提供上下文 │ 應用程式  │
  │ urce │ 供應商提供的型錄、價目表、產  │ ，例如檔案內容、資料 │ （Host）  │
  │ s    │ 地資料，拿來看、當參考        │ 庫紀錄               │ 決定要不  │
  │      │                               │                      │ 要附上    │
  ├──────┼───────────────────────────────┼──────────────────────┼───────────┤
  │ Prom │ 供應商設計好的套餐範本，例如  │ 預先寫好的提示模板， │ 使用者主  │
  │ pts  │ 「海鮮三吃組合」，客人點了就  │ 例如 /review-code    │ 動選用    │
  │      │ 照流程走                      │ 這種斜線指令         │           │
  └──────┴───────────────────────────────┴──────────────────────┴───────────┘

  口訣：Tools 是「動手」，Resources 是「看資料」，Prompts 是「照範本」。

❯ B

  跟你對話時，自己判斷「現在應該寄信」，就呼叫它寄出了一封信。請問 send_email

  - D. Client

  請回答 A、B、C 或 D。

✻ Brewed for 3s · done 下午1:15

❯ C                                                                             

⏺ 答對了。send_email 符合 Tool 的兩個特徵：

  - 執行動作：真的寄出一封信，改變了外部狀態。
  - 由 AI 決定呼叫：是模型自己判斷「現在該寄信」。

  就像主廚請供應商「幫我送貨過來」，是動手做事，不只是拿資料來看。

  就照固定格式產出摘要。請問這個 /summarize-meeting 最可能是哪一類？

❯ C                                                                             

⏺ 答對了。/summarize-meeting 有兩個 Prompt 的典型特徵：

  - 由使用者主動選用：是你自己輸入斜線指令觸發的，不是 AI 自己決定。
  - 預先寫好的範本：流程和輸出格式都是事先設計好的。

  就像客人點了「海鮮三吃套餐」，廚房就照固定流程出菜。

  某個 MCP Server 把公司的「產品規格文件」開放出來，讓 Host 可以把文件內容附加給
  AI 當參考。AI 只能讀這份文件，不能修改。請問這份產品規格文件屬於哪一類？

  - A. Tool
  - B. Resource
  - C. Prompt

✻ Worked for 3s · done 下午1:16

❯ B                                                                             

⏺ 答對了。產品規格文件符合 Resource 的特徵：

  - 唯讀資料：只能看，不能改，用來提供上下文。
  - 由應用程式（Host）決定附上：是 Host 把內容附加給 AI 參考，不是 AI
    呼叫它去做事。

  就像供應商提供的型錄和價目表，主廚拿來參考，但不會因此動到任何東西。

  最容易搞混的是 Tool 和 Resource，可以用這個問題來分：

  - 只是讀取資料當參考？那就是 Resource。

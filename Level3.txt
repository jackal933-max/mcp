❯ FastMCP和MCPServer有什麼不同？                                                

  Ran 5 shell commands (ctrl+o to expand)

⏺ 兩者基本上是同一個東西：官方 Python SDK（mcp 套件）在 2.x 把 FastMCP 改名成
  MCPServer，順便調整了一些 API。我在 scratchpad 另外裝了 mcp 2.3.0，把這次的
  server 搬上去跑了一遍，差異如下。

  對這個 server 有影響的

  1. import 和類別名稱。 舊的 import 在 2.x 會直接丟
     ModuleNotFoundError，沒有相容層。

  # v1
  from mcp.server.fastmcp import FastMCP
  mcp = FastMCP("weather")
  # v2
  from mcp.server.mcpserver import MCPServer
  mcp = MCPServer("weather")

     @mcp.tool() 和 mcp.run() 的用法沒變。只改這兩行，三個 tool 在 v2
     都能正常回傳。
  2. 錯誤訊息的處理方式（這點比較要注意）。
     - v1：tool 丟出任何 exception，例外訊息都會照原樣傳給 client。
     - v2：只有丟 ToolError 的時候，訊息才會傳給模型。其他
       exception（包括我們用的 ValueError）一律當成程式崩潰，模型只會看到 Error 
       executing tool get_current_weather。
     - 我實測過：查「東京」時，v1 會回「找不到城市 '東京'，可用城市：…」，v2
       只剩那句通用錯誤。
     - 所以如果升到 v2，server.py 裡的 raise ValueError(...) 要改成 raise 
       ToolError(...)，Claude 才看得到可查的城市和日期範圍。
  3. client 端的欄位名稱改成 snake_case。 例如 CallToolResult.isError 變成
     is_error。這只影響自己寫 client 的情況，像我的測試腳本就因此壞掉。server
     端不受影響。

  v2 新增的東西

  MCPServer 的建構參數多了
  middleware、extensions、cache_hints、subscriptions、resource_security
  這些，也能在建構時直接傳入 tools=[...]。這個天氣 server 都用不到。

  名稱容易搞混的地方

  另外還有一個獨立的第三方套件也叫 fastmcp（pip install fastmcp，用 from fastmcp
  import FastMCP）。官方 SDK 早期的 FastMCP
  就是從它併進來的，後來兩邊各自發展，現在是兩個不同的專案。官方改名成
  MCPServer，部分原因應該就是為了避開這個混淆，不過這是我的推測。

  建議

  目前鎖在 mcp<2（1.30.0）沒問題，可以繼續用。如果想升到 v2，要改的只有上面第 1
  點的兩行 import/類別名稱，加上第 2 點把 ValueError 換成
  ToolError。要升級的話跟我說。

  上一步我用 CLI 模式跑的就是這個指令，已經確認能連上。

  做法二：留在現在的網頁，手動改連線欄位

  在左側欄位填入：

  - Transport Type：STDIO

  - Arguments：/Users/gilbert.hung/Project/mcp/weather-mcp/server.py

  填好再按 Connect。

  會另外建一個臨時環境，不會用到你的 .venv。我建議用做法一。
